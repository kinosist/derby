# derby(授業用オンライン対戦競馬)Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** クラス全員が1つの部屋で同じ自動レースに架空コインを賭け、所持金を競う Android アプリと、先生が進行を操作する管理ページ、それらをつなぐ Cloudflare サーバーを作る。

**Architecture:** Cloudflare Worker が `/ws` の WebSocket を固定名の Durable Object「Room」1個に渡す。Room がゲーム状態の唯一の正で、状態が変わるたびに各接続へその人向けのスナップショット全体を送る。ゲームのルールは通信から切り離した純粋関数(`rules.ts` / `game.ts`)に置き、Room は薄い殻にする。生徒は Flutter アプリ、先生は Worker が配信する静的な管理ページ(`/admin`)から同じ WebSocket でつながる。

**Tech Stack:** Flutter 3.41 / Dart ^3.11.5(`web_socket_channel`, `shared_preferences`)、Cloudflare Workers + Durable Objects(SQLite-backed、Hibernation WebSocket API)、TypeScript、wrangler、vitest、Node 22。

**Spec:** `docs/superpowers/specs/2026-11-15-derby-design.md`(必ず併読すること)

## Global Constraints

- 表示文言はすべて日本語。アプリは縦向き固定、管理ページは横長向け。
- 架空コインのみ。課金・換金・実在の馬名は扱わない(馬名は架空)。
- 定数: `TOTAL_RACES = 5`、`START_COINS = 1000`、`HORSES = 8`、`MIN_BET = 10`(10 コイン単位)、`RESCUE_COINS = 100`(賭け受付開始時に所持金 `< 10` の人)、`RACE_DURATION_MS = 20000`、`NAME_MAX = 12`(文字数は Unicode コードポイントで数える)、最大参加者 `MAX_PLAYERS = 60`。
- オッズ `= max(1.1, round(1/p, 小数1桁))`。払い戻し `= floor(賭け金 × オッズ)`(賭け金込み)。賭け金は締め切り時に引く。
- サーバーが唯一の正。端末から来た所持金・結果は一切信用しない。レースの結果と映像データは締め切り後に初めて送る。
- 進行操作は `TEACHER_KEY` で認証済みの接続からのみ受け付ける。
- アプリの追加パッケージは `web_socket_channel` と `shared_preferences` のみ。管理ページはフレームワーク・ビルド工程なしの HTML + JS。
- 馬・コースは画像素材を使わずコードで描く。
- Cloudflare 無料プランで動くこと(Durable Object は `new_sqlite_classes` で定義)。
- 接続先: アプリは `String.fromEnvironment('SERVER_URL', defaultValue: 'ws://10.0.2.2:8787/ws')`。
- このフォルダは git 管理されていない。Task 1 の最初に `git init` し、以後タスクごとにコミットする(push はしない)。
- Cloudflare へのデプロイ(`wrangler login` / `wrangler deploy`)は実行しない。手順書に書き、依頼者が行う。

## Review Focus

1. **先生がボタンを連打・二重送信する**(「締め切ってレース開始」「次のレースへ」を2回)→ フェーズに合わない操作は無視され、レースが飛ばされたり二重精算されたりしない。(Task 2)
2. **同じ生徒が二重に接続する**(アプリを開き直した直後で古い接続が残っている、同じ名前+同じIDで再参加)→ 参加者は増えず、古い接続が閉じられ、所持金はそのまま。(Task 2, 3)
3. **壊れた・想定外のメッセージ**(JSON でない、巨大、`amount` が小数/負数/文字列、存在しない馬番、未参加での賭け)→ エラー応答だけ返り、部屋は落ちず他の人に影響しない。(Task 2, 3)
4. **レース中の途中参加・復帰・サーバー再起動**(racing の途中でアプリを開き直す、Durable Object が休止から復帰)→ レースは経過時間に合った位置から再生され、時間が来れば必ず result に進む。(Task 3, 7)
5. **名前の入力**(前後の空白、空白だけ、絵文字、13文字、他人と空白違いの同名)→ 前後の空白は除いて判定し、空と13文字以上は拒否、絵文字入り12文字は通る。(Task 2, 6)

## 通信仕様(全タスク共通)

クライアント → サーバー(JSON テキスト、1通 2KB 超は拒否):

| メッセージ | 内容 |
|---|---|
| `{"t":"join","id":string,"name":string}` | 生徒の参加・復帰 |
| `{"t":"admin","key":string}` | 先生として認証 |
| `{"t":"bet","horse":1..8,"amount":int}` | 賭ける/変更する |
| `{"t":"cancelBet"}` | 賭けの取り消し |
| `{"t":"adminAction","action":A,"playerId"?:string}` | `A` = `start` / `closeAndRace` / `next` / `newGame` / `reset` / `kickAll` / `kick` |

サーバー → クライアント:

- `{"t":"error","code":C,"message":日本語}`。`C` = `bad_message` / `bad_name` / `name_taken` / `room_full` / `bad_key` / `bad_bet` / `not_allowed` / `kicked`。
- `{"t":"state", ...View}`:

```ts
type Phase = 'lobby' | 'betting' | 'racing' | 'result' | 'final';
type View = {
  phase: Phase; raceNo: number; totalRaces: number; serverNow: number; // epoch ms
  horses: { no: number; name: string; odds: number }[];        // lobby/final では []
  players: { id: string; name: string; coins: number; online: boolean; rank: number;
             hasBet: boolean }[];                               // 所持金の多い順。hasBet は admin 以外には常に false
  betCount: number; onlineCount: number;                        // 接続中の生徒のみ
  me: { id: string; name: string; coins: number; rank: number;
        bet: { horse: number; amount: number } | null;
        lastResult: { horse: number; amount: number; won: boolean; delta: number } | null } | null;
  race: { startedAt: number; durationMs: number; order: number[];   // 着順の馬番
          times: number[][] } | null;                           // racing/result のみ。times[馬番-1] は 11 個の累積 ms
  bets: { playerId: string; horse: number; amount: number; delta: number }[]; // result のみ、他は []
  isAdmin: boolean;
};
```

`times`: コースを 10 区間に分けた 11 地点(スタート=0 を含む)の通過時刻。各配列は単調増加、最後の値がゴール時刻。ゴール時刻の小さい順が `order` と一致し、全馬 `15000 ≤ ゴール時刻 ≤ 19000`。

**Files:**

- Produces(`game.ts`、すべて純粋関数。引数の state は変更せず新しい state を返す。「通信仕様」の `Phase` と `View` 型もこのファイルで定義して export する):

```ts
export type ErrorCode = 'bad_message'|'bad_name'|'name_taken'|'room_full'|'bad_key'|'bad_bet'|'not_allowed'|'kicked';
export type Player = { id: string; name: string; coins: number; online: boolean;
  bet: { horse: number; amount: number } | null;
  lastResult: { horse: number; amount: number; won: boolean; delta: number } | null };
export type GameState = { phase: Phase; raceNo: number; horses: Horse[]; players: Player[];
  race: { startedAt: number; durationMs: number; order: number[]; times: number[][] } | null };
export type R = { state: GameState; error?: ErrorCode };
export function newGame(): GameState;                                   // lobby, raceNo 0
export function normalizeName(raw: unknown): string | null;             // trim、1..12 コードポイント、それ以外 null
export function join(s: GameState, id: string, rawName: unknown, newId: () => string):
  R & { playerId?: string; replacedId?: string };                       // replacedId: 閉じるべき古い接続の持ち主
export function setOnline(s: GameState, playerId: string, online: boolean): GameState;
export function placeBet(s: GameState, playerId: string, horse: unknown, amount: unknown): R;
export function cancelBet(s: GameState, playerId: string): R;
export function adminStart(s: GameState, rng: Rng): R;                   // lobby → betting(第1レース)
export function adminCloseAndRace(s: GameState, rng: Rng, now: number): R; // betting → racing
export function finishRace(s: GameState): GameState;                     // racing → result(精算)。racing 以外は何もしない
export function adminNext(s: GameState, rng: Rng): R;                    // result → betting、最終レース後は final
export function adminNewGame(s: GameState): R;                           // final → lobby(参加者は残す)
export function adminReset(s: GameState): R;                             // どのフェーズでも → lobby(参加者は残す)
export function kick(s: GameState, playerId: string): R;
export function kickAll(s: GameState): R;                                // 部屋を空にして lobby
export function viewFor(s: GameState, playerId: string | null, isAdmin: boolean, now: number): View;
```

決めごと:
- `join`: 名前で人を決める。(a) 同名がいない → 新規(`START_COINS`、`MAX_PLAYERS` 超は `room_full`)。渡された id が既存の別名の参加者と重なるなら `newId()` を使う。(b) 同名が切断中 → その参加者として復帰し、id を渡された id(重なるなら `newId()`)に付け替える。(c) 同名が接続中で id も同じ → 復帰、`replacedId` に同じ id を返す(古い接続を閉じる)。(d) 同名が接続中で id が違う → `name_taken`。成功時は `online: true`。
- 新規参加は phase を問わず `START_COINS`、`bet: null`。betting 中の参加はそのレースから賭けられる。
- `placeBet`: phase が betting、参加者が存在、`horse` は 1..8 の整数、`amount` は整数かつ 10 の倍数かつ `10 ≤ amount ≤ coins`。違えば `bad_bet`(未参加は `not_allowed`)。既存の賭けは上書き。
- `adminCloseAndRace`: 賭け金を所持金から引き、`drawOrder` と `makeTimes` で `race` を作る(`startedAt = now`)。
- `finishRace`: 的中者に `payout` を加算。各参加者の `lastResult`(`delta` は差し引き。的中 `payout − amount`、外れ `−amount`、賭けなしは `null`)を設定。`bet` はここでは消さず result の `bets` 公開に使い、次の betting 開始時に消す。
- betting 開始時(`adminStart` / `adminNext`): `makeField` で出走馬を作り、`bet` と `lastResult` を消し、所持金 `< 10` の人を `RESCUE_COINS` にする。
- `adminNext`: `raceNo === TOTAL_RACES` なら final。
- `adminNewGame` / `adminReset`: 全員 `START_COINS`、`bet`/`lastResult`/`race`/`horses` を消す。
- フェーズに合わない操作はすべて `not_allowed`(state は元のまま)。
- `viewFor`: `players` は所持金の降順(同額は名前順)、`rank` は同額同順位(1,1,3)。`hasBet` は `isAdmin` のときだけ実値。`betCount`/`onlineCount` は接続中の生徒のみ。`race` は racing/result のみ。`bets` は result のみ(全員分、`delta` 付き)。`horses` は `prob` を含めない。`me` は `playerId` が null または存在しなければ null。racing 中、`me.coins` は賭け金を引いた後の値。

- `wrangler.jsonc`: `durable_objects.bindings: [{ name: "ROOM", class_name: "Room" }]`、`migrations: [{ tag: "v1", new_sqlite_classes: ["Room"] }]`、`assets: { directory: "./public" }`。書き方は実装時に Cloudflare の現行ドキュメント(Durable Objects の WebSocket Hibernation、Static Assets)を確認して合わせること。

- `room.ts`(`DurableObject` を継承):
  - 状態は `GameState` 1個。変更のたびに `ctx.storage.put("state", state)`。コンストラクタで `blockConcurrencyWhile` により読み込み(なければ `newGame()`)、`ctx.getWebSockets()` と突き合わせて `online` を正す。
  - 接続は `ctx.acceptWebSocket(ws)`。接続ごとの身元は `ws.serializeAttachment({ role: 'none' | 'player' | 'admin', playerId? })`。
  - `webSocketMessage`: 文字列でない・2048 文字超・JSON でない・`t` が不明 → `bad_message` を返すだけ。`join` 成功時は attachment を player にし、`replacedId` があればその接続に何も送らず `close(4000, "replaced")`。`admin` は `key === env.TEACHER_KEY` なら attachment を admin に、違えば `bad_key`。`adminAction` は admin 以外 `not_allowed`。`kick` / `kickAll` では対象の接続に `kicked` エラーを送って `close(4001, "kicked")`。
  - 状態が変わったら全接続に `viewFor` の結果を `{t:"state",...}` で送る(role none には送らない)。エラーは送信元にだけ返す。
  - `adminCloseAndRace` 成功時に `ctx.storage.setAlarm(startedAt + RACE_DURATION_MS)`。`alarm()` で `finishRace` して配信。コンストラクタでの読み込み時に phase が racing で時刻を過ぎていれば即 `finishRace`、過ぎていなければアラームを張り直す(Review Focus 4)。`adminReset` / `kickAll` ではアラームを消す。
  - `webSocketClose` / `webSocketError`: player なら、同じ playerId の接続が他に残っていない場合に限り `setOnline(false)` して配信。
  - 例外は握りつぶさずログに出すが、1通のメッセージ処理の失敗で他の接続に影響させない(try/catch で `bad_message`)。
- `scripts/sim.mjs`(Node 22 組み込みの `WebSocket` を使用、依存なし): `--url`(既定 `ws://localhost:8787/ws`)、`--key`(既定 `dev`)、`--players`(既定 40)。手順: admin 接続 → `kickAll` → N 人が join → `start` → 各レースで全員がランダムに賭け(1割は見送り)→ `closeAndRace` → result を待つ → `next` を 5 レース → final。検証して失敗なら exit 1:
  - 全クライアントが各フェーズの state を受け取る。betting 中に `race` が null(結果が漏れない)。
  - 各クライアントが自分で計算した所持金(`floor(amount×odds)`)とサーバーの `me.coins` が毎レース一致。
  - racing から result まで 19〜23 秒。
  - **Review Focus 2**: 1人が同じ id・名前で2本目の接続を張る → 1本目が閉じられ、`players.length` が N のまま。
  - **Review Focus 3**: `"not json"`、3000 文字の文字列、`{"t":"bet","horse":99,"amount":-5}`、未参加の接続からの `bet`、生徒からの `adminAction` を送る → それぞれ error が返り、その後も試合が続く。
  - **Review Focus 4**: racing 開始 8 秒後に新しい接続で既存の生徒が復帰 → 受け取る state の `race.startedAt` が元の値のまま、`serverNow − startedAt` が 7000〜10000。
  - 間違った key での `admin` → `bad_key`。最後に `kickAll` で片付け。
