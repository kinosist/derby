# 授業用オンライン対戦競馬アプリ「derby」設計書

日付: 2026-11-15

凡例: 【依頼者】= 依頼者が決めたこと / 【提案】= 設計者の判断(依頼者は未確認。変更可)

## 1. ねらい

学校の授業で、クラス全員が同じレースに架空コインを賭け、最終的な所持金を競うアプリ。

- 【依頼者】プレイヤーは馬を操作しない。レースは自動で走る。
- 【依頼者】賭けた結果、所持金が一番多い人が勝ち。
- 【依頼者】学校の授業で使う。ルーム(部屋)は1つでよい。
- 【依頼者】端末は Android Studio のエミュレータ。
- 【依頼者】サーバーは Cloudflare を使う。
- 授業の具体的なねらい(確率の学習か、レクリエーションか等)は未回答。【提案】「ルールが一目で分かり、盛り上がる」ことを優先する。

## 2. ゴール / 対象外 / 避けたいこと

**ゴール**
- 生徒はアプリを開いて名前を入れるだけで、全員同じ部屋に入れる。
- 先生が進行をボタンで操作し、全員が同じレースを同じタイミングで見る。
- 1試合(既定5レース)を終えると、所持金順の最終順位が出る。
- 1クラス40人程度が同時に参加できる。
- 生徒がアプリを閉じても、開き直せば続きから参加できる。

**対象外(作らない)**
- 実際のお金・課金・換金。扱うのは架空コインのみ。
- 複数の部屋、アカウント登録、ログイン、チャット、フレンド機能。
- 単勝以外の馬券(複勝・馬連など)。
- 過去の試合の履歴保存。
- iOS / Web / デスクトップ向けの調整(Android エミュレータで動けばよい)。
- 馬の育成・操作。

**避けたいこと(動いても失敗)**
- 生徒1人の切断や未操作で、クラス全体の進行が止まること。
- 生徒がレース前に結果を知れること、所持金を端末側で書き換えられること。
- 先生以外が進行を操作できること。
- 当日、先生が手順に迷うこと。

## 3. 進め方の候補と決定

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| 先生PCでサーバー | 校内LANで先生PCに接続 | 登録不要、データが校外に出ない | ファイアウォール設定、校内でPC同士が通信できる必要 |
| Firebase | Google のクラウドDB | サーバー起動不要 | Google側の設定作業、端末が正とならず不正対策が弱い |
| **Cloudflare(採用)** | Workers + Durable Objects | サーバー起動不要、部屋1つの常時接続に向く、サーバーが唯一の正 | Cloudflare アカウントとデプロイ作業が必要 |

【依頼者】Cloudflare を採用。

【提案】Cloudflare の中での構成は **Worker 1つ + Durable Object 1つ(部屋そのもの)+ WebSocket**。部屋が1つなので、Durable Object 1個に全員が WebSocket でつながり、そこがゲームの状態を持つ唯一の正になる。D1 や KV を別に使う案は、部屋1つ・履歴不要のこの用途では部品が増えるだけなので採らない。

## 4. ゲームのルール

すべて【提案】。

- 1試合 = 5レース。開始時の所持金は全員 1,000 コイン。
- 各レースは8頭立て。馬名・勝率はレースごとにサーバーが決める。
- 馬券は単勝のみ。1レースにつき1頭に、10コイン単位で 10〜所持金全額まで賭けられる。賭けない(見送り)も可。
- 賭け受付中は、賭けの変更・取り消しができる。先生が締め切った時点の内容で確定。
- オッズは固定式(賭けの集まり方で変動しない)。`オッズ = 1 ÷ 勝率` を小数1桁に丸め、最低 1.1 倍。胴元の取り分は設けない。
- 配当: 賭け金は締め切り時に所持金から引かれる。当たり → `賭け金 × オッズ`(端数切り捨て)が払い戻される(賭け金込み)。外れ → 何も戻らない。例: 300 コインを 5.1 倍に賭けて当たると 1,530 が戻り、差し引き +1,230。外れると −300。
- 着順はサーバーが勝率に基づいて抽選する(勝率の高い馬ほど上位に来やすい)。
- 救済: 賭け受付が始まる時点で所持金が 10 コイン未満(最低賭け金に届かない)の人は、所持金を 100 コインにする(授業中に何もできない生徒を出さないため)。
- レース数(5)と開始所持金(1,000)はサーバー側の定数。先生画面での設定変更は作らない。
- 最終順位は所持金の多い順。同額は同順位。
- 他人の賭けの内容は受付中は見えない(賭けた/まだ、だけ先生に見える)。結果画面で公開する。順位表(名前と所持金)は常に全員に見える。

## 5. 進行(フェーズ)

先生がボタンで次へ進める。自動では進まない(説明を挟めるように)。

```
受付(lobby) → 賭け受付(betting) → レース中(racing) → 結果(result)
                    ↑                                      │
                    └──────── 次のレース ───────────────────┘
                               最終レース後 → 最終結果(final) → 新しい試合(lobbyへ)
```

- lobby: 生徒が名前を入れて参加。先生画面に参加者一覧。先生が「試合開始」。
- betting: 出走馬とオッズを表示。先生画面に「賭け済み n / m 人」。先生が「締め切ってレース開始」。
- racing: 全端末で同じレース映像(約20秒)を再生。サーバーは締め切り時に結果と映像データを作り、その時点で初めて配信する。映像の時間が過ぎるとサーバーが自動で result に進める(ここだけ自動)。
- result: 着順、各自の当たり外れと配当、順位表。先生が「次のレースへ」。
- final: 最終順位。先生が「新しい試合」で lobby に戻る(参加者は残り、所持金はリセット)。
- 途中参加: 試合中に入った生徒は 1,000 コインで次の賭け受付から参加。
- 先生はいつでも「試合をリセット」できる(確認ダイアログあり)。参加者は残したまま lobby に戻り、所持金と賭けを消す。

**参加者の出入り**(すべて【提案】)
- 参加者は名前で区別する。端末に保存したIDは、開き直したときに名前入力を省くためだけに使う。
- 接続が切れた参加者は部屋に残る(順位表に「切断中」と表示)。「賭け済み n / m 人」の m は接続中の生徒だけを数えるので、切断した生徒を待つ必要はない。
- 同じ名前の参加者が**切断中**なら、その名前で入った人がその参加者として復帰する(所持金を引き継ぐ)。エミュレータのデータが消えた・入れ直した場合もこれで戻れる。同じ名前の人が**接続中**なら入れない。
- 保存されたIDが、別の名前で接続中の参加者と重なった場合(PCが複製イメージの場合など)は、新しいIDを振り直して別人として扱う。
- 先生画面に「全員を退出させる」ボタン(確認あり)。部屋を空にして lobby に戻す。別のクラスで使う前に押す。
- 先生は参加者一覧から個別に退出させることもできる(ふざけた名前や入り間違いへの対処)。

## 6. 画面

【依頼者】アプリは生徒用のみ。先生モードはアプリに入れず、先生はサーバーが配信する管理ページ(Webページ)をPCのブラウザで開いて進行を操作する。

表示は日本語。アプリは縦向き。

**アプリの入口画面**: 名前入力(1〜12文字、同じ名前の人が接続中なら入れない)と「参加」ボタン。

**生徒画面(アプリ)**

```
第3レース / 全5レース        賭け受付中
あなた: 1,400コイン  (2位 / 32人)
────────────────────────
1 ハヤテオー       2.4倍
2 ミドリノカゼ     5.1倍
3 ゴールドラッシュ 12.0倍
 ...(8頭、タップで選択)
────────────────────────
賭け金 [-] 300 [+]  [全額]   当たれば 1,530
[ この内容で賭ける ]   (賭けた後は「変更」「取り消し」)
```

- racing: コースを横から見た図で8頭が走る映像。自分が賭けた馬を強調。
- result: 着順、自分の結果(「的中! +1,230」/「はずれ −300」。差し引きの増減を表示)、順位表。
- final: 最終順位と自分の順位。

**先生用の管理ページ(ブラウザ、スクリーン投影を想定)**

- サーバーの `/admin` を PC のブラウザ(Chrome / Edge)で開く。最初に先生用パスワードを入力する。【提案】パスワードはそのブラウザに保存し、開き直しても再入力は不要。
- 横長の画面向けに作る。

```
第3レース / 全5レース   賭け受付中   賭け済み 28 / 32人
1 ハヤテオー 2.4倍 ... (出走表)
順位表(上位と全員をスクロール)
[ 締め切ってレース開始 ]              [試合をリセット]
```

- フェーズごとに主ボタンが1つだけ出る(試合開始 / 締め切ってレース開始 / 次のレースへ / 新しい試合)。
- racing では生徒と同じレース映像を大きく表示。
- 参加者一覧(接続中/切断中、個別に退出させる操作)と「全員を退出させる」もここにある。
- 先生は賭けに参加しない。

アプリも管理ページも、接続が切れたら画面上部に「再接続中…」を出し、自動で再接続する。

## 7. 構成

```
derby/
  lib/            Flutter アプリ(Android、生徒用のみ)
  server/         Cloudflare Worker + Durable Object(TypeScript)+ 先生用管理ページ
  docs/           設計書、先生向け手順書
```

**サーバー (server/)**
- Worker: `/ws` への WebSocket 接続を、固定名の Durable Object「Room」1個に渡す。
- Room: 参加者・フェーズ・レース・賭け・所持金を持ち、ストレージに保存する(Durable Object が休止・再起動しても試合が続くように)。WebSocket は Hibernation API を使う。
- ゲームのルール(オッズ計算、着順抽選、配当、フェーズ遷移)は、通信と切り離した純粋な関数群として書き、単体テストする。
- 管理ページ: Worker が `/admin` で配信する静的な Web ページ(HTML + JavaScript、フレームワークやビルド工程なし)。生徒アプリと同じ WebSocket でつながり、同じ状態スナップショットとレース映像データを受け取って、ブラウザ側でレースを描く。レース映像の描画はアプリ(Dart)と管理ページ(JavaScript)の2か所に実装することになるが、どちらもサーバーの同じデータを補間するだけなので、見た目は揃えつつ別々に書く。
- 先生の認証: 先生用パスワードを Worker のシークレット `TEACHER_KEY` に置く。管理ページからの接続時に照合し、進行操作は認証済みの接続からのみ受け付ける。管理ページ自体は誰でも開けるが、パスワードなしでは何も見えず操作もできない。
- Cloudflare 無料プランで動く構成にする。

**通信**
- JSON メッセージ。クライアント → サーバー: 参加、賭ける/取り消す、先生の進行操作。
- サーバー → クライアント: 状態が変わるたびに、その人向けの状態スナップショット全体を送る(公開情報 + 本人の賭け)。40人規模なので差分配信はしない。
- 本人識別: アプリが初回に作るランダムなIDと名前を端末に保存し、再接続時に送る。同じIDなら同じ参加者として復帰(詳細は「参加者の出入り」)。
- レース映像データ: 各馬の通過タイム列(コースを区切った各地点の通過時刻)をサーバーが着順と矛盾しないように作って送る。端末はそれを補間して描くだけ。racing の途中で入り直した端末は、サーバーのレース開始時刻から経過分を進めた位置から再生する。

**アプリ (lib/)**
- 追加パッケージは `web_socket_channel` と `shared_preferences` のみ。状態管理は Flutter 標準(ChangeNotifier)。
- 接続先URLはビルド時に `--dart-define=SERVER_URL=...` で指定。未指定時はローカル開発用(`ws://10.0.2.2:8787/ws`、エミュレータから開発PCを指すアドレス)。
- 馬とコースは画像素材を使わず、アプリ内で描く(色付きの馬番ゼッケン+簡単な馬の形)。馬名は架空のもの。

## 8. 確認方法

- サーバーのルール部分は単体テスト(オッズ、配当、着順と映像データの整合、フェーズ遷移、救済、同順位)。
- アプリは状態の読み取りと主要画面のウィジェットテスト。
- 通し確認: 開発PCで `wrangler dev` によりサーバーをローカル起動し、ブラウザの管理ページで進行を操作しながら、エミュレータ(+複数の擬似クライアント)で1試合を最初から最後まで通す。40接続での進行も擬似クライアントで確認する。
- 本番(Cloudflare へのデプロイ)は依頼者のアカウントでのログインが必要なので、手順書を用意し、ログイン操作は依頼者が行う。

## 9. 依頼者にお願いする作業

- Cloudflare アカウントの用意と `wrangler login`(ブラウザでの承認)。
- 先生用パスワードを決める。

## 追記 (2026-11-15): 本物らしさの強化

【依頼者】本物に近いパラメータを設定する。馬の調子を表示する。出走前に馬の表情を出す。コースを長くしてスクロールさせる。調子と表情は勝敗に影響させる(案A)。

### 候補と決定
- **A(採用)**: オッズは馬の実力だけで決め、当日の調子は勝率にだけ効かせる。出走表と表情をよく見た生徒が有利になる。
- B: 調子も表情も飾り。作りは簡単だが、見る意味が薄い。→ 不採用。

### 馬のパラメータ(すべて【提案】)
- 表示のみ: 性別(牡・牝・セ)と年齢(3〜7歳)、馬体重(420〜520kg)と前走からの増減、人気順(オッズの低い順)。
- 近3走の着順: 実力の高い馬ほど良い着順になりやすい(ばらつきあり)。
- 脚質(逃げ・先行・差し・追込): レース展開に反映する。逃げは序盤に前へ出て終盤に鈍り、追込は終盤に伸びる。勝率には影響しない。
- レースごとに距離(1200 / 1400 / 1600 / 1800 / 2000 / 2400m、芝)と馬場状態(良・稍重・重・不良)を決める。馬場は表示と走破時間(重いほど遅い)にだけ影響する。

### 調子と表情
- 各馬に本当の調子が5段階ある(絶好調・好調・普通・不調・絶不調)。**本当の調子そのものは端末に送らない。**
- オッズは実力(調子を含まない勝率)から従来どおり計算する。実際の勝率は「実力の勝率 × 調子の倍率」を正規化したもの。倍率は 絶好調 1.7 / 好調 1.3 / 普通 1.0 / 不調 0.8 / 絶不調 0.55。
- 出走表の「調子」と「表情」は、どちらも本当の調子の手がかり。それぞれ独立に 80% の確率で本当の調子どおり、20% で1段階ずれる(当てにならないことがある)。2つが揃っている馬ほど信頼できる。
- 表情は5種類: 気合十分 / ごきげん / 落ち着き / そわそわ / 眠そう(絶好調〜絶不調に対応)。顔はコードで描く(画像素材なし)。賭け受付中に、アプリと管理ページの出走表に出す。

### コースとスクロール
- コースを画面幅の 3〜5 倍(距離が長いほど長い)にし、先頭の馬を追ってカメラが横に流れる。スタート直後とゴール前は端で止まる。
- 残り距離の表示、200m ごとの標識、全馬の位置が分かる小さなバー(全体図)を付ける。
- レース時間は距離に応じて約 24〜32 秒(従来は約 20 秒)。結果への自動進行はレースごとの時間に従う。

### 互換性
- 追加項目はすべて従来のメッセージへの追加。アプリは項目が欠けていても動く(古いサーバーにつないでも落ちない)。

## 追記 (2026-11-15): 馬券の種類と複数購入

【依頼者】複勝・馬連・3連単を追加する。1レースに複数の馬券を買えるようにする。

### 馬券(当たりの条件は【依頼者】の選択、細部は【提案】)
| 種類 | 選ぶ馬 | 当たり |
|---|---|---|
| 単勝 `win` | 1頭 | 1着 |
| 複勝 `place` | 1頭 | 3着以内 |
| 馬連 `quinella` | 2頭(順不同) | 1・2着の組み合わせ |
| 3連単 `trifecta` | 3頭(順番あり) | 1・2・3着が順番どおり |

- 倍率はすべて固定式。馬の実力(調子を含まない勝率)から、着順が「残った馬の中で実力に比例して決まる」と仮定して的中確率を計算し、`max(1.1, min(999.9, round(1/確率, 小数1桁)))` とする。調子は倍率に入らない(従来どおり、調子の良い馬は倍率より来やすい)。
- 払い戻しは馬券ごとに `floor(賭け金 × 倍率)`。倍率は買った時点のものを馬券に記録する。
- 1レースに最大 10 点。賭け金は 10 コイン単位で、全馬券の合計が所持金以下。同じ種類・同じ馬の馬券をもう一度買うと、金額を置き換える。締め切りまで 1 点ずつ取り消せる。
- 結果画面では、自分の馬券ごとの的中・払い戻しと合計の増減を出す。ほかの人については、買った馬券の内容と合計の増減を公開する。

### 通信(従来への追加)
- 倍率表は、賭け受付が始まったとき(と、受付中に参加・復帰したとき)に 1 回だけ `{t:"odds", raceKey, place, quinella, trifecta}` で送る(3連単は 336 通りあり、状態の更新のたびに送ると無駄が大きい)。状態には対応する `raceKey` を入れる。単勝の倍率は従来どおり `horses[].odds`。
- 購入: `{t:"bet", type, horses:[…], amount}`。取り消し: `{t:"cancelBet", id}`。
- 状態の `me` に `tickets`(買った馬券)と `results`(結果)を追加。
- **古いアプリとの互換**: 従来の `{t:"bet", horse, amount}` は「単勝 1 点に買い直す」、`{t:"cancelBet"}`(id なし)は「全部取り消す」として扱う。`me.bet` と `me.lastResult`、`bets[].horse/amount/delta` も従来の形で送り続ける。
- 以前の形式で保存された部屋の状態(`bet` を持つ参加者)は、読み込み時に新しい形へ直す。

### 画面
- アプリ: 賭け画面の上部で馬券の種類を選ぶ。単勝・複勝は 1 頭、馬連は 2 頭、3連単は 1着→2着→3着の順にタップ。金額を決めて「この馬券を買う」。買った馬券は一覧に出て、1 点ずつ取り消せる。
- 管理ページ: 出走表に複勝の倍率を追加。結果に各自の馬券の内容を出す。
